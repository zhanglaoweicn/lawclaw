# 数据与隐私说明

给律师用、又要在公开仓库里讲清楚的东西，所以写明白：

## 一、数据存在哪里（全部在本机）

| 数据 | 位置 | 说明 |
|---|---|---|
| 案件台账、日程、会话、配置、律师画像 | 桌面端的 WebView **localStorage** | 键名前缀 `lawclaw_` |
| 案件文书、文件、案件时间轴 | WebView **IndexedDB**（库名 `LawClaw`） | 保存为本地记录 |
| 后端状态（Hermes 会话库、技能缓存、值守快照、cron 输出） | `backend/.hermes/` | 由 `HERMES_HOME` 指向，**隔离**于用户全局 `~/.hermes/` |
| 凭证 | `backend/.env` | 已在 `.gitignore` 中，不入库 |

**彻底清空**：桌面端删掉应用数据目录（或应用内页脚的「恢复演示数据 / 重置演示数据」），
后端删掉 `backend/.hermes/`。

本仓库**不含**任何用户数据：`.gitignore` 排除了 `backend/.env`、`backend/.hermes/` 的
运行时状态（sessions / state.db / logs / cache / USER.md），发布脚本还有一道自检专门拦这些。

## 二、什么内容会离开本机

程序本身不上传代码或文件，但**以下操作会把内容发往你配置的第三方服务**，请按执业保密要求判断：

1. **AI 对话**：你输入的问题，以及被注入的上下文——**当前案件的字段**（当事人、案号、期限、
   标的额等）、**案件文档片段**（`kb_search` 选出的 top-5 片段）、**历史经验召回**、
   **对话附件解析出的文本**，都会随提示词发往你配置的 LLM 端点。
2. **法条/案例检索**：检索关键词发往元典开放平台；法条时效验证会把**法律名称**发往
   国家法律法规数据库（NPC，公开库）。
3. **企业信息查询**：企业名称发往元典企业库。

> 实务建议：对含当事人真实身份、隐私、商业秘密的内容，先做必要脱敏再提问，或改用本地/私有
> 部署的模型端点（应用支持任意 OpenAI 兼容端点，填内网地址即可）。

## 三、凭证怎么存

- LLM 的 API Key：首启向导或「配置」页填写，存本机 localStorage，**随请求**传给后端
  （后端据此构造 agent，不落盘到仓库）。
- 元典 Key：写在安装目录 `backend/.env` 的 `YUANDIAN_API_KEY`。
- 两者都**不进 git**；打包脚本默认不把任何密钥写进产物（`BUILD_INFO.txt` 里会标注是否注入）。

## 四、演示数据声明

- 演示版首启灌入的 10 个案件、当事人、案号、金额、期限**全部为虚构**，与任何真实当事人无关；
  案号形如 `(2026)京0105民初12345号` 是编造格式，不对应真实案件。
- 为避免与真实主体产生联想，演示数据与测试数据中的企业名已统一替换为虚构名称
  （本文档更新时核对过：不再出现真实知名企业名）。
- 测试用例中的手机号、身份证号等为**上游示例或数字字面量**，非真实个人信息。

本项目为律师辅助工具。所有 AI 输出均为**供执业律师复核的草稿**，不构成法律意见，
不得直接对外出具。使用者对最终文书与结论负专业责任。
